Visual build spec

One document, decisions made. This merges the surface review and the palette directions into an implementation spec for the Hyprr homepage. No layout changes, no copy changes, no new sections. Colour, type, density, motion and the scroll section only. Rationale is in appendix A — build from parts 1–10.

Palette: Ink & Engines — decided Fonts: Archivo + JetBrains Mono — decided Repo: D:\Projects\hyprrbrands Next 16.3 · Tailwind 4 Est. 7 working days
What this changes, in one paragraph

The homepage stops having a purple primary. Colour becomes information — Citrus is Build, Lime is Grow, Aqua is Operate, everywhere and always — carried on a white ground with Ink fields. Type collapses from fifteen ad-hoc sizes to a six-step scale with a 17 px body floor. The scroll section gains dwell so its four states can actually be read, and mobile gets a real composition instead of having its visuals removed.

Every layout, every grid, every string of copy stays exactly as built.

The one rule that must not be broken

Every colour on the page resolves to an engine, a neutral, or a semantic state. No Citrus in a Grow section. No Aqua used because a card looked empty. Three colours applied loosely becomes confetti, and the whole argument for this palette is that colour carries information. If a designer or developer cannot say which engine a colour instance belongs to, it should be a neutral.

Button rule — derived from contrast, not taste

Section groundPrimary CTASecondary CTAButton edge
White / Bone / pastel bandInk fill, white text1px --color-line border, ink text17.89
Ink fieldCitrus fill, ink text1px rgb(255 255 255 / .30), white text11.60
Never: Citrus fill on a white or pastel ground1.54

A UI control needs 3:1 against its own background to have a visible edge. A Citrus button on white is 1.54:1 — the fill and the page are the same brightness and the button loses its shape. This is why the CTA changes fill by ground rather than staying one colour.

2Type system and fonts

The font change

Space Grotesk and Inter both sit on impeccable’s reflex-reject list — the training-data defaults that produce visual monoculture. Since the brand is open, they go. The replacement is one family in real weight contrast plus a proper mono, which is stronger than a timid display-plus-body pair.

RoleFaceWhy this one
Display + textArchivo variable, wght 100–900A grotesque drawn from signage — sturdy, plain-spoken, industrial, which is the voice of a business that moves physical goods. Weight 800 at display size and 400 at text size gives genuine contrast inside one family. Proper tabular numerals for the operational panels. This document is set in it.
MonoJetBrains Mono 400 / 600Labels, SKUs, state markers, panel data. Already the mono named in the homepage build spec, so this is a continuation rather than a new decision. The build currently falls back to ui-monospace, which renders differently on every machine — that is why the mono labels look inconsistent between screenshots.
RetiredSpace Grotesk · InterBoth on the reflex-reject list. Removing them also cuts one font family and four static weights from the critical path.

If more character is wanted later

Swap the display face only and leave text and mono alone: Bricolage Grotesque (free, real personality, variable optical size) or a licensed grotesque — Söhne, Diatype, Aeonik, Founders Grotesk. Do this after the palette has shipped and settled. Changing palette and display face in the same week means you cannot tell which one worked.

Two unit bugs to fix while you are in there

1. vh in type clamps. SystemScroll.tsx sets the state heading to clamp(24px,4vh,44px). On a 13″ laptop that resolves to about 28 px while the rest of the page is at 52 px. Every type clamp uses vw, never vh.

2. Clamp floors are set backwards for mobile. On a 375 px screen the measure is irrelevant and size is the only lever, yet the floors are the smallest values on the page. Raise every floor to the step values above.

The map applies on mobile unchanged. It matters more on a phone: when only one column is visible, colour change is the only cue that you have moved between ideas.

5Scroll section rebuild

The pinned mechanic is kept. Six changes, none of which touch the layout or the state content.

5.1 Dwell — the fix for “not smooth”

Today SCROLL_LEN = 320 vh drives a continuous lerp against raw scroll progress. Four states across 320 vh with continuous interpolation means no state ever holds still — the moment one arrives it starts leaving, so four states of content register as one long smear. That is the “not smooth” complaint; it is not a frame-rate problem.

Fix: remap p before it reaches paint(). Each handoff spends 55% of its scroll holding a state still and 45% animating between. Nothing else in the paint loop changes.

// SystemScroll.tsx — add above paint(), then wrap p once

const N    = 4;      // states
const HOLD = 0.55;   // share of each segment held still
const EDGE = HOLD / 2;

// clamp01 and ease already exist in this file
function dwell(p: number) {
  const seg = clamp01(p) * (N - 1);            // 0 → 3
  const i   = Math.min(Math.floor(seg), N - 2);
  const t   = seg - i;                          // 0 → 1 inside this handoff
  const k   = clamp01((t - EDGE) / (1 - HOLD)); // still, then move, then still
  return (i + ease(k)) / (N - 1);
}

// then, at the single point where progress enters the paint loop:
//   const p = dwell(rawProgress);
// leave every existing lerp/mix call untouched.

Tuning. Ship at SCROLL_LEN = 320. With 55% held, the three handoffs get about 48 vh each. If they feel rushed on a trackpad, raise to 380 — do not lower HOLD, because the stillness is the point.

The component renders all four in JSX and only styles them imperatively, so it should pass — confirm it with JS off before touching the paint loop, and again after. Same for prefers-reduced-motion: all four states must read as a stacked list, not collapse to state 1.

Subtraction first. The page runs five permanent ambient animations and one repeated fade — the exact profile that reads as generated.

Delete

7Mobile spec

Mobile is currently a narrower desktop with the visuals removed. That is the most expensive defect in the build, and it is one function.

// SystemScroll.tsx, applyMode() — what happens below 900px today
if (grid) grid.style.display = "none";
if (rail) rail.style.display = "none";
if (cue)  cue.style.display  = "none";

The four panels, the progress rail and the scroll cue are all removed, leaving four stacked text blocks. In Hero.tsx the listing and storefront fragments are hidden min-[900px]:block, so they never appear either. The mobile homepage is a documentary because the code deletes the visuals. Given that most of your traffic will be mobile, this is the highest-value fix in the spec.

ElementToday (<900px)Build this instead
Scroll statesPanels, rail and cue display:none. A snap carousel passes the three 375 px requirements the build spec already sets — all four states reachable, ticks usable, a fast flick does not skip states 2 and 3 — by construction. A hidden grid passes none of them.

8Imagery brief

The page needs imagery. It does not need stock photography of people, and the existing build spec is right to ban it.

The rule that cannot be relaxed

Build spec section F: “No stock photography of people, and no AI-generated faces. Not on the team section, not as ambient imagery. This is the one irreversible mistake available on this page.” You sell to people burned by ecommerce operators whose sites are wallpapered with smiling stock consultants. One stock businessman puts Hyprr in that visual category on sight, and a sceptical buyer’s association cannot be undone. Also banned: no faces, and no screens showing numbers — a laptop with a rising graph is an implied earnings claim.

#AssetBrief

Given colour on hover, correct optical sizing and a legible micro-label each, that row does more for trust in one screenful than any photograph — and it is a day of work. AWhy — the evidence

Condensed from the surface review and the palette directions. Read this if you need to defend a decision above; skip it if you are building.

A.1 Why violet went

It is an orphan in the palette. By hue: Coral 7° · Citrus 42° · Lime 81° · Aqua 170° · Sky 211° · Rose 345° — and Violet at 251°, alone in a 134° gap. Every other colour has a neighbour. That is why the accents read as decoration rather than as a system, and why the page felt like something was missing when nothing was technically wrong. Ink at 252° meant the neutrals carried the same cast, which is why the retint to #17171A is part of the change and not cosmetic.

It cannot carry the accents as a field. Measured as a full-bleed ground, Violet Deep #4E2FD6 gives Aqua 4.38:1 (fails AA) and Coral 2.91:1 (unusable) — the worst of every candidate tested on four of five accents. A violet section could only ever be violet-and-white, losing the multi-colour identity in the exact place it was meant to be shown off.

A.2 Why Ink & Engines rather than a new brand colour

ThreeEngines.tsx already assigns Citrus to Build, Lime to Grow and Aqua to Operate. SystemScroll.tsx carries the same mapping through all four states. The colour system is already built — it is being rendered at seven pixels. Promoting it costs no new token, requires no guideline rewrite, and makes colour carry information instead of decoration: a visitor learns within two sections that amber means Build and teal means Operate, and every page after that is faster to read.

It is also the cheapest decision to reverse. If it reads too austere in three months, adding a field colour on top of a working engine-coded system is a two-token change. Going the other way is not. Petrol #08424C + Citrus is the reserve option if a single primary is wanted later.

A.4 What the reference sites actually share

Lemon Squeezy, Pattern and My Amazon Guy look nothing like each other, which is what makes the comparison useful. The one move all three make: a background that changes hard, at least four times down the page. Lemon Squeezy’s purple hero is not a gradient or a glow effect — it is a solid rectangle of committed colour you cannot scroll past without registering. Hyprr’s #FAFAF7 and #FFFFFF differ by 1.05:1; that is not an alternation, it is the same colour twice. Part 3 is the fix, and the “glow” comes from the commitment, not the hue.

Why the “vs White” column is not a failure.
